ThinkAlong is a small, portable AI workflow for people who want useful outcomes without learning prompt engineering. It helps an AI understand the goal, ask only consequential questions, do the work when possible, and check the actual result.

> **Status: experimental, v0.3.0.** The repository includes repeatable test cases and validation tooling. It does not yet claim measured improvement in task success or user satisfaction. Native skill support varies by platform.

## Why ThinkAlong?

AI often fails in two ways: it misunderstands what someone means, or it understands the request but returns an incomplete or unsuitable result. Rewriting the prompt alone does not reliably fix either problem.

ThinkAlong focuses on four behaviors:

1. **Understand** the intended outcome, constraints, and existing context.
2. **Clarify** only information that materially changes the result or prevents a meaningful risk.
3. **Do** the useful work using the lightest adequate process.
4. **Check** the actual deliverable, repair specific gaps, and report what is and is not verified.

### A small example

**Request:** “Help me organize my Downloads folder, but don't delete anything.”

- A poor workflow asks a long list of preferences or starts moving files immediately.
- ThinkAlong first inspects what is available, chooses a reversible organization proposal, preserves the no-deletion constraint, and checks the final inventory if changes are made.

This is a design example, not a claim that every model or host has been behavior-tested.

## Install

Use the ZIP generated by the repository packaging script, or download the install package from Releases after a release has been published.

### Codex

Copy `skills/think-along/` to one of these locations:

- Personal: `~/.agents/skills/think-along/`
- Project: `.agents/skills/think-along/`

Then invoke it explicitly with `$think-along`. See the [Codex skill documentation](https://developers.openai.com/codex/skills).

### Claude

- **Claude Code:** copy the folder to `~/.claude/skills/think-along/` for personal use, or `.claude/skills/think-along/` for a project.
- **Claude web app:** upload the generated ZIP in **Customize → Skills** when custom Skills are available for your account and code execution is enabled.

See [Claude Skills documentation](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills).

### ChatGPT web

If Skills are enabled for your account/workspace, open **Plugins → Skills → Create → Upload from your computer** and upload the generated ZIP. Availability depends on the plan, workspace settings, and product rollout; see the [official ChatGPT Skills guide](https://help.openai.com/en/articles/20001066-skills-in-chatgpt).

### DeepSeek and other AI tools

- **DeepSeek through a compatible host** (for example, Codex configured with a DeepSeek model or a host that supports Agent Skills): install the skill using that host's skill directory and instructions.
- **DeepSeek chat website or another chat UI without native Skills:** copy [`adapters/portable-instructions.md`](adapters/portable-instructions.md) into custom instructions, a system prompt, or the beginning of a conversation. This provides the core behavior, but does not add file access, tools, or automatic skill discovery.

ThinkAlong follows the open [Agent Skills format](https://agentskills.io/specification), but **not every AI product natively supports Skills**. See the [platform compatibility guide](docs/platform-compatibility.md) for the current distinctions and limitations.

## What it is—and isn't

**It is:** a reusable workflow for intent clarification, task execution, repair, and evidence-based verification.

**It isn't:** a universal capability unlock, a guarantee of correctness, or a prompt generator that rewrites every request. It cannot grant a model tools, permissions, memory, web access, or file access that the host does not provide.

## Evaluate it

The repository separates two questions:

- [`evals/task-cases.md`](evals/task-cases.md): when ThinkAlong is active, does it behave well across task types?
- [`evals/trigger-cases.md`](evals/trigger-cases.md): should the skill activate for this request, or would activation add unnecessary friction?

Run local structural checks and validator tests:

```bash
python -m pip install -r requirements-dev.txt
python scripts/validate_skill.py
python -m unittest discover -s tests -v
python scripts/package_skill.py
```

These checks validate files, metadata, package structure, and the validator itself. They do **not** simulate an LLM or prove runtime behavior. For a performance claim, run the same cases with and without ThinkAlong using the same model, tools, context, and scoring rubric, then publish the results and limitations.

## Design principles

- Outcome over prompt polish.
- Reuse context; do not ask the user to repeat known information.
- No fixed question-count quota: each question must justify its cost.
- Keep simple tasks simple; scale effort to complexity and risk.
- Prefer reversible defaults, but never invent personal facts or bypass critical consent.
- Verify with actual evidence; never claim checks that were not run.
- Keep core instructions portable and platform-specific installation guidance separate.

## Contributing

Useful contributions include real failure cases, trigger misses, false activations, platform-specific installation fixes, and reproducible tests. Please include the input/context, expected behavior, observed behavior, and a regression check. Do not claim performance improvements without recorded baseline results. See [`CONTRIBUTING.md`](CONTRIBUTING.md) and the [public release checklist](docs/release-checklist.md).

If ThinkAlong is useful, consider starring the repository and sharing a concrete task where it helped—or where it failed. Both are valuable feedback.
