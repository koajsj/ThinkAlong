# Contributing to ThinkAlong

Thanks for helping make AI collaboration more useful and less frustrating.

## Useful contributions

- Reproducible cases where the Skill asks an unnecessary question or misses a necessary one.
- False activations or missed activations, with the exact prompt and host/model.
- Cases where it misunderstands requirements, skips useful work, or overstates verification.
- Platform installation issues and focused improvements with static evidence.

## Before opening a pull request

1. Explain the user problem.
2. Include exact input/context, expected behavior, observed behavior, and why the difference matters.
3. Record observable acceptance criteria and source evidence; do not add test code or case catalogues.
4. Run only static validation and the package-structure checks described in README. Do not run unit, runtime, behavioral or model tests under the current policy.
5. Keep changes focused and avoid mandatory steps that do not fix a demonstrated failure.
6. Keep behavioral/model evaluation unrun under the current policy. The retained rubric and protocol describe evidence requirements if evaluation is separately authorized later; they do not authorize it or prove improvement.

Keep English and Chinese documentation aligned. Do not add credentials, private conversations, or sensitive personal data to repository files or public issues.
